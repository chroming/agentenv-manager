## What's changed

- Skill update checks and previews are faster. Repository metadata, prepared candidates, and file comparisons are reused instead of repeating the same Git and filesystem work.
- Batch Skill updates now prepare shared source data once, reducing duplicated repository access when several Skills come from the same source.
- Added customer-environment compatibility coverage for startup recovery, app-data upgrades, Target layouts, duplicate runtime Skills, and Apply failure paths.
- macOS direct and Homebrew packages now use the same fixed project identity. After the one-time transition from an older direct build, future upgrades should no longer repeatedly ask for Keychain access because the application identity changed.
- Release validation now checks the pinned macOS certificate and designated requirement across direct/Homebrew channels and both architectures, while preserving the expected Gatekeeper rejection for a non-notarized build.
- Updated the README and product screenshots to match the current interface.

## Update

Homebrew users can update with:

```bash
brew update
brew upgrade --cask chroming/tap/agentenv-manager
```

Direct installations can use `Settings > General > App updates`. Browser-downloaded macOS packages are still not notarized and require the first-install Open Anyway approval.

Direct installers for macOS, Windows, and Linux are attached to this Release after the native build and packaged-app checks complete.
