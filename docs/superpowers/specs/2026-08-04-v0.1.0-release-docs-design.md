# AgentEnv Manager v0.1.0 Release Documentation Design

## Goal

Prepare the public documentation and screenshots for the first `v0.1.0` release. Every product claim must match the current application and current CI evidence.

## Public README

Keep `README.md` and `README.en.md` short enough to scan before installation. Both versions use the same structure:

1. What AgentEnv Manager manages and what it leaves to each Agent.
2. Installation and the unsigned macOS boundary.
3. Five core workflows: Agents, Profiles, isolated Profile Compare, Skill Library, and Conversations.
4. Safety and privacy boundaries.
5. Source development, verification, packaging, and contribution links.

The README must name all six built-in Agent integrations and distinguish verified packaged startup from real third-party CLI compatibility.

## Screenshots

Regenerate these five public images from the current renderer:

- `docs/images/agents.png`
- `docs/images/profiles.png`
- `docs/images/profile-compare.png`
- `docs/images/skills-by-source.png`
- `docs/images/conversations.png`

The existing capture fixture remains the source of truth. It uses a temporary AgentEnv data root, a temporary Home, fake Agent commands, fixed dates, public example repository addresses, and synthetic conversations. Captures must not contain `/Users/`, internal domains, tokens, email addresses, or real local repositories.

## Supporting Documentation

Update the documentation index, development guide, testing strategy, and verification snapshot where current behavior or release evidence has changed. Product contracts remain unchanged unless the audit finds a factual contradiction.

Historical specs and plans are records of earlier decisions and are not rewritten as current user documentation.

## Verification

Before tagging:

- Build the current renderer before capture.
- Generate all mock captures successfully.
- Inspect the five public images at their published size.
- Scan public documentation and image metadata for private paths, internal domains, credentials, and fixture leaks.
- Run punctuation checks for Chinese and English README files.
- Run repository release verification and confirm a clean worktree after committing.
- Confirm `package.json` is version `0.1.0` and no `v0.1.0` tag or Release already exists.

Create an annotated `v0.1.0` tag only after these checks pass. Push the commit first, then push the tag so the existing Release workflow builds and publishes the exact documented revision.
