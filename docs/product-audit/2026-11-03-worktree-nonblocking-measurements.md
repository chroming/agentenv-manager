# 工作树统计不阻塞操作

## Change Evidence Card

- 症状：可见工作树仍要等全部空间统计结束才能操作。
- 契约：目录身份和实时 Git 安全检查决定可操作性；大小和日期只是辅助数据，不能充当全页操作锁或清理授权。
- 根因：inspect 在返回安全检查结果前遍历目录测量；Renderer 将扫描写进共用 busy；Preview 对缓存行要求等一次完整扫描。
- 归属：工作树扫描/统计调度、显示缓存、页面刷新状态；不是调整按钮 CSS 或缩短超时。
- 影响状态：首次扫描、缓存重启、手动刷新、统计失败、统计完成晚于清理、窗口关闭；列表、仓库动作、检查、清理、恢复三语言三尺寸。

## 行为与复用

- Git 登记和安全检查先返回列表。空间/修改日期由独立的最多两 worker 只读任务补齐。
- 沿用 ResourceRow、InteractiveStatus、CatalogSortMetric、RefreshAction；未新增控件样式。行显示中性统计文字，仓库显示汇总进度，不禁用现有选择和操作。
- scanning 和用户操作 busy 分离。缓存行在刷新时仍能选中；前台操作取消自己已过时的刷新回复。
- 缓存只提供候选身份。按项动作重新读取真实登记、HEAD、状态、索引和当前管理决定，Preview/Remove 仍独立校验指纹。不用旧大小或旧可清理标记批准删除。
- 统计更新只改日期/大小及统计状态，不改 Git 安全状态、不清空选择。相同扫描的 revision 防止晚到 IPC 回复覆盖新统计。
- 统计发布合并到最多每 100ms 一次，最终完成必发布；不会因每个小文件/工作树完成都重刷全页。
- 统计失败不让目录失去操作能力，未知大小不当零。统计不延长五分钟 Git 新鲜度。
- 新扫描和变更会取消旧统计，变更不等待统计目录遍历；旧结果不能复活已移除行或失效缓存。
- 缓存写入与失效顺序化；服务关闭取消读取，只等待已开始的缓存发布，不等待可选统计。
- 本轮未引入 AI 请求、依赖、真实目录变更或安装包行为调整。
