# AI 调用可靠性收敛

## Change Evidence Card

- 症状：返回中一个分类或可选字段异常使整份结果失败；限流、额度不足和参数不兼容无法区分；缓存损坏可能阻断重新生成。
- 用户目标：手动分析已经选中的内容，获得简短、有依据的结果；不额外发送数据、不自动增加调用，不修改资源。
- 负责层：共享请求、返回解析、结果缓存；业务层保留各自任务和证据验证。
- 同类范围：更新摘要、新 Skill 摘要、标签、Profile、Compare、重复版本、工作树；设置连接测试。
- 组件映射：进度 -> InteractiveStatus；局部错误 -> Notice + DiagnosticMessage；结果说明 -> 共享 AIResponseNotice；原返回只读查看 -> SyntaxCodePreview；保存恢复 -> Button。不新增页面 CSS 或改变窗口几何。
- 证据：异常响应与传输测试、坏缓存/保存失败测试、Renderer 测试、当前构建的隔离 Electron Mock API 流程与多尺寸截图。

## 行为契约

1. 保持一次手动动作最多一次网络请求，不自动重发、切换地址或模型；取消、超时、过滤和工具调用不伪装成功。
2. 已知服务的参数差异由请求适配层拥有。严格结构化输出仅用于已知支持的服务/模型；未知兼容接口继续 JSON 模式，不通过自动付费探测协商。
3. 只做可证明等价的本地格式规范化。未知分类保留为未分类，不降级成普通/无风险发现；不可解析条目保留在受限的原返回中，并明显说明结果不完整。
4. 文件/文档引用使用请求内短 ID。软件映射回精确身份，绝不从相似文件名、路径前缀或模型给出的任意地址补证据。
5. 空、截断或过滤的响应不是完整分析；只有语法完整且可验证的 JSON 才可形成结构化结果。截断但 JSON 完整的结果必须标为部分结果。
6. 缓存是派生数据。坏缓存不阻断生成，成功替换前保留坏文件；重新生成失败保留旧结果。保存失败返回可见的未保存结果，同一次进程内可只重试保存而不再次调用模型。
7. 普通日志不保存 Prompt、响应正文、推理、Key 或供应商原始错误正文；仅记录受限的错误类别、HTTP 状态、请求 ID、参数名和等待时间。
8. 只有当前请求接收自己的进度；准备、等待、接收、解析和保存共用状态词汇；原资源操作永远不依赖 AI 成功。

## 2026-10-31 发布回归补充

- 主分支 CI、独立发布回归和原样重跑均在 Node 22 的 250 文件输入校验中超过默认 5 秒；不增加超时或删减文件数。
- 负责层为 `analysisBudget.ts`：旧算法在这个输入中完整序列化请求内容 2587 次，改为精确累计每个文档在双重 JSON 转义后的字节数，只计算一次完整空信封；保留系统预算、脱敏、Unicode、截断、遗漏及全部输入哈希语义。
- 新增 7 个确定性回归，覆盖序列化次数、原算法结果等价、多字节和转义字符、空文档、大标签和超限说明。改动前次数断言实际失败（2587 对 1），改动后通过。
- Node 22.23.4 和 Node 26.12.0 的 38 个相关用例均通过；本机同一 Node 22 大输入用例的独立复测从约 2.10 秒降至 68 毫秒，不把本机耗时视为所有设备的性能承诺。本次没有 UI、数据格式或请求次数变化。
